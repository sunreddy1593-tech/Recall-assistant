# Build spec: "Recall" — guided filters for half-remembered photos (MVP)

You are building a working, deployable MVP for a product-management graduation project.
Read this whole spec first, then build in the milestone order at the end. Ask me only if
something blocks you; otherwise make sensible choices and note them in README.md.

---

## 1. Context (why this exists)

- Goal metric: increase the % of users who successfully retrieve a photo they remember but
  cannot precisely describe.
- Research finding (root cause): people remember photos as **episodes** — an *era* of life
  ("my boy-cut era", "before COVID", "when I worked in Ireland"), an occasion, who was there,
  what they wore — but photo apps only accept **one precise cue** (an exact date, a face, or a
  keyword). Users translate eras into years in their heads and scroll; it fails when the era is
  fuzzy and the subject is common (e.g. themselves).
- Survey (n = 63): only 13% typed a search; 65% scrolled; 41% remembered life context, 41% a rough
  time, only 8% the exact date; top request = "filter by what I remember (time, people, place)".
- Target user: **the Moment Sharer** — a memory comes up mid-conversation and they need the photo
  in seconds to show someone.

**The MVP:** guided, AI-built filters — *When (incl. eras) · Where · Who · What happened* — that
narrow each other in any order, then show **3–5 "moment" cards** ("Is it one of these?") instead of
a flat grid. Users *recognise* options instead of *recalling* keywords.

## 2. Tech stack and constraints

- **Python 3.11 + Streamlit** (single app), pandas, Pillow, `reverse_geocoder` (offline place
  names), `requests`. No database: precomputed JSON/Parquet index files in the repo.
- **AI provider: Google Gemini API** (Google AI Studio key) for vision labelling and text tasks.
  Model names are config values (`GEMINI_VISION_MODEL`, `GEMINI_TEXT_MODEL`), default to the current
  cheapest *Flash* model listed in AI Studio. Optional: Groq (`GROQ_API_KEY`, model
  `openai/gpt-oss-120b`) as a text fallback.
- **All vision work happens offline** in a build script. The live app makes **at most 2 small text
  calls per search** (era parsing, optional detail re-ranking). Everything else is plain logic.
- Deploy target: **Streamlit Community Cloud** (public link). Secrets via `st.secrets`:
  `GEMINI_API_KEY`, optional `GROQ_API_KEY`, optional `LOG_WEBHOOK_URL`.
- Never commit secrets. Add `.streamlit/secrets.toml` to `.gitignore`; ship
  `.streamlit/secrets.toml.example` with placeholders.
- Must work if AI calls fail (rule-based fallbacks below). Must never crash on a missing field.
- No Google logos or trademarks in the UI. Neutral, clean look inspired by modern photo apps.

## 4. Offline build script — `scripts/build_index.py`

Run once (`python scripts/build_index.py`); writes `data/index.json`. Steps:

1. **Read metadata:** EXIF date + GPS via Pillow; fill gaps from manifest. Skip unreadable files with a
   warning.
2. **Place names:** if `place_override` → use it as venue. Else reverse-geocode lat/lon offline
   (`reverse_geocoder`) → `city`, `region`, `country`. No coords → `place = "Unknown place"`.
3. **Events (moments):** sort by time; start a new event when the gap to the previous photo > 6 hours
   OR distance > 30 km. Each event: id, start, end, photo ids, dominant place, people union.
4. **Vision labels (Gemini, batched):** per photo send the image (≤ 768px) and get strict JSON:
   `{"caption": str (≤ 20 words), "scene": "indoor|outdoor", "activity": str, "objects": [str],
     "clothing_colours": [str], "text_in_image": str, "mood": str}`.
   Batch up to 8 images per request; retry with backoff; cache results in `data/vision_cache.json`
   keyed by file hash so re-runs are free.
5. **Event labels (Gemini, text-only):** from the captions of an event's photos produce
   `{"event_label": "Birthday dinner", "event_type": "celebration|trip|everyday|work|school|food|document|screenshot|other"}`.
   Photos of bills, receipts, IDs, tickets and screenshots must get `document` or `screenshot`
   (community research: 12 of 23 retrieval threads had a practical intent; 6 involved screenshots).
   Short, human labels (2–4 words).
6. **Chapters:** assign every photo/event to chapters by date (can be several).
7. Write `index.json` with `photos`, `events`, `chapters`, `people`, plus build stats.
8. `--no-ai` flag: skip steps 4–5 and use placeholder labels (so the UI can be built first).

## 5. App — screens and behaviour

### 5.1 Layout
- **Sidebar:** "Test session" box — participant code (P1…P9 or "Guest"), task picker
  (Task 1–6 = scenarios above + "Free search"), **Start task** button (starts a timer), and
  **Give up** button. Library stats below.
- **Main page "Find a photo you half-remember":** header, then the **filter panel**, then the
  **live counter** ("23 photos · 4 moments match"), then **moment cards**.
- Pages: `Find a photo` (main), `How it works` (for evaluators), `Test results` (aggregated logs).

### 5.2 Filter panel — five facets that narrow each other in ANY order
Each facet shows options **computed from photos matching the other selected facets** (true faceted
search), each option with a **count**, plus an explicit **"Not sure / Any"** choice. Multi-select allowed.

1. **When**
   - Chips of **life chapters** with counts (e.g. "College · 2018–22 (64)").
   - "Year" quick chips, a **before / after / between** selector, optional month.
   - **"Describe the time in your own words"** text box → AI era parser (§6.1) → shown as an
     editable chip: "Interpreted as Sep 2023 – Aug 2024 (Masters in Scotland) ✎".
2. **Where** — places in scope, grouped City → venue, with counts; searchable.
3. **Who** — people chips (simulated face groups) with counts; "Just me" and "Not sure".
4. **What happened** — AI event labels in scope (e.g. "Birthday dinner (3)", "Beach day (2)"), with a
   tiny thumbnail each.
5. **Type** — "Photos · Screenshots · Documents" chips with counts (from `event_type` / vision labels).
   Screenshots and documents are NOT grouped into time/place events: each one is its own item, and the
   results show them as single-item cards. For these, the "Anything else you remember?" box searches
   `text_in_image`, caption and objects (e.g. "bill", "electricity", "boarding pass").

**Optional "Describe it" box (top of the page, M4):** one text field — "Describe what you remember, like
you'd tell a friend". The text model turns it into filter chips (When range or chapter, Who, Where,
What, Type, and leftover details for "Anything else"), returned as strict JSON and only using values
that exist in the index. The chips appear pre-selected and editable, then the normal moment cards show.
Fallback: era regex + keyword match against people/place/event names. Users who prefer can ignore the
box and use the filters directly.

Optional fifth input, collapsed by default: **"Anything else you remember?"** (e.g. "I was wearing a
mask", "red saree", "uniform") → re-ranks results (§6.2).

Every change updates all facet counts and the result list instantly (no AI call except the era box and
the detail box). Show a "Clear all" link.

### 5.3 Results — moment cards, not a grid
- Show the **top 3–5 moments** (events) for the current filters, ranked by: number of matched facets
  → detail re-rank score → fewer photos first (more specific) → recency.
- Each card: event label, date range ("14 Feb 2019 · evening"), place, people, **4 thumbnails**,
  "N photos", and a button **"Is it in here? Open"**.
- Below cards: "None of these? → **Show 5 more** · or answer one quick question".
- **Narrowing question (rule-based, no AI):** if > 5 moments match, find the facet whose values best
  split the candidates (highest entropy among event_type, scene, place, people) and ask one
  question with buttons, e.g. "Was it closer to… [Birthday dinner] [Beach day] [Office]" or
  "Indoors or outdoors?". Clicking applies that filter.

### 5.4 Moment view
- All photos of the moment in a grid + a **"Before / After" strip** showing the neighbouring
  moments (people find photos via nearby photos).
- Clicking a photo opens a large view with **"✅ This is the photo"** and **"Not it"**.
- "✅" ends the task: show "Found in 0:38 · 6 steps", log success, offer "Try another task".

### 5.5 "How it works" page (for evaluators)
One-screen explanation with a simple diagram: offline AI labelling → index → faceted filters → moment
cards. A table **"Where AI is used"**: era → date range (LLM); event labels and photo captions
(vision model, precomputed); "anything else" re-ranking (LLM); place names (plain location data, no
AI); people (simulated face groups). Plus the demo-library disclaimer.

### 5.6 "Test results" page
Reads logs (§7) and shows, per participant and task: found? (yes/no/gave up), time to find, steps
(filter changes + opens), filters used, whether the era box was used. Summary tiles: task success %,
median time, median steps. CSV download. No personal data beyond participant codes.

## 6. AI features (exact behaviour)

### 6.1 Era parser
Input: the user's phrase + today's date + `chapters.csv` (names, ranges, aliases).
Prompt the text model to return strict JSON:
`{"start": "YYYY-MM-DD", "end": "YYYY-MM-DD", "matched_chapter": str|null, "confidence": 0-1,
  "explanation": "≤ 12 words"}`.
Examples to include in the prompt: "before COVID" → up to 2020-03-15; "college first year" → first 12
months of the College chapter; "when I was in Scotland" → Scotland chapter; "summer 2019" →
2019-04-01..2019-07-31 (Indian summer); "around 3-4 years ago" → relative to today.
**Fallback (no AI / error / low confidence < 0.5):** regex for years and ranges ("2019", "2018-2020",
"before 2020", "after 2021", month names) + alias match against chapters. If nothing matches, show
"Couldn't place that — pick a chapter instead" and highlight chapter chips.

### 6.2 "Anything else you remember" re-ranking
Take up to 60 candidate photos (after filters); send their ids + captions/objects/clothing to the text
model with the user's detail; get back up to 10 ids ranked with a 0–1 relevance score. Boost moments
containing them. **Fallback:** keyword overlap between the detail and caption/objects/clothing fields.

### 6.3 Cost and safety
- Cache AI responses in `st.cache_data` keyed by input text.
- Timeouts 15 s; never block the UI — show a spinner and fall back.
- Never send photos to the AI at runtime.

## 7. Logging for user testing

Log every meaningful event as JSON:
`{"ts", "session_id", "participant", "task", "event", "detail", "filters", "n_photos",
  "n_moments", "elapsed_s", "step"}`
Events: `task_start`, `filter_change` (facet + value), `era_parsed` (input → range, used_fallback),
`detail_rerank`, `question_answered`, `moment_open`, `photo_view`, `photo_confirmed`, `gave_up`.
- If `LOG_WEBHOOK_URL` is set: POST each event (fire-and-forget, 5 s timeout) — it goes to an n8n
  webhook that appends rows to a Google Sheet tab `mvp_logs`.
- Always also append to a local `logs/events.jsonl` and offer a download on the Test results page.
- The Test results page reads from the Google Sheet's public CSV export if `LOGS_SHEET_CSV_URL` is set,
  else from the local file.

## 8. Look and feel
- Clean, light, photo-first: white cards on a warm off-white background, generous thumbnails,
  rounded 12px corners, one accent colour (teal `#0D9488`), dark slate text `#0F172A`.
- Fonts: Inter (body), Plus Jakarta Sans (headings) via Google Fonts CSS in `st.markdown`.
- Accessible: text ≥ 14px, contrast ≥ 4.5:1; never rely on colour alone (labels/icons with words);
  keyboard-usable buttons; alt text on images (use captions).
- Mobile-friendly widths (testers may open it on a phone): cards stack on narrow screens.

## 10. Acceptance criteria
1. With `--no-ai` index, the full UI works end to end (filters, counts, moments, confirm, logs).
2. Facets narrow each other in any order; every option shows a correct count; "Not sure" never
   dead-ends (there is always at least one way back to results).
3. Era box: "before COVID", "college first year", "when I was in Scotland", "2019", "summer 2019"
   all produce sensible ranges (AI or fallback) and an editable chip.
4. Each of the 6 test scenarios can be found in ≤ 6 steps by someone who knows only the
   episode, not the date.
5. Results show 3–5 moment cards (never a flat grid of 100 photos).
6. Logging captures task start → confirm/give-up with elapsed time and step count.
7. Unit tests pass for filtering, era fallback and ranking. App starts on Streamlit Cloud with the
   committed `data/index.json` and works without any API key (fallbacks only).
